# MACR v0.6.0a1 T1 Operability Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add globally observable reconciliation, a real one-attempt T1 dispatcher path, and reproducible quiet census gates without activating a live provider route.

**Architecture:** An exact private T1 manifest binds ordered tasks, route proposals, token policies, costs, and targets. A host staging command creates both rich batch authority and existing dispatch authority, while a production worker claims one row and traverses the existing MacrRuntime/Vault/event/accounting path exactly once.

**Tech Stack:** Python dataclasses, SQLite WAL/fencing, existing `MacrRuntime` and authority stores, PowerShell census scripts, `unittest` multiprocess controls.

**Spec:** `docs/superpowers/specs/2026-08-30-macr-v0.6.0a1-t1-operability-design.md`

## Global Constraints

- This plan executes after `2026-08-30-macr-v0.6.0a1-model-token-policies.md` and consumes its exact policy digest APIs.
- Release tag `v0.6.0a0` remains immutable; version advances to `0.6.0a1` only at the final task.
- No provider retry, fallback, model substitution, auto-materialization, autonomous verification, or acceptance.
- Future live limits are T0 USD 0.005; T1 3 x USD 0.005, aggregate 0.015; campaign 0.020; GLM 128K context/8,192 output.
- Tests use fake providers and D-drive test state; no key, real provider, shared migration, merge, tag, or deployment.
- Execute inline; implementation subagents are not authorized.
