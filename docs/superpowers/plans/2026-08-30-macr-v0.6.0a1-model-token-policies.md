# MACR v0.6.0a1 Model-Scoped Token Policies Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace global token settings with exact provider/model policies while raising external context/output defaults and keeping local Qwythos conservative.

**Architecture:** Add a pure model-token policy registry plus an append-only D-drive override store. Direct runtime resolves policy from each conversation's pinned provider/model; delegated runtime validates each task against the resolved exact policy before authority or transport.

**Tech Stack:** Python dataclasses, SQLite WAL, existing Direct settings/server/UI, existing ProviderRegistry/MacrRuntime, `unittest`, PowerShell offline gates.

**Spec:** `docs/superpowers/specs/2026-08-30-macr-v0.6.0a1-model-token-policies-design.md`

## Global Constraints

- Base is exact `v0.6.0a0` commit `683101636edd5e840c9a2809fc85a575add18bf7` / tree `070519796d4bbbd8e73e7f63eeb0402b86eaaab1`.
- External built-ins use the exact table in the spec; Qwythos remains 8,192 context / 4,096 output.
- T1 live GLM policy remains 128,000 context / 8,192 output and does not inherit ordinary external defaults.
- Persistent policy state is absolute on D:. Tests use D-drive `test-tmp` only.
- No provider call, credential read, shared runtime migration, live route, merge, tag, or deployment.
- Every behavior uses RED -> GREEN -> refactor and a focused commit.
- Execute inline in the primary task; implementation subagents are not authorized.
