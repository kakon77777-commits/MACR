# MACR v0.6.0a1 Model-Scoped Token Policies — Engineering Design

**Status:** Approved for offline implementation by Neo on 2026-08-30  
**Base:** `v0.6.0a0` -> commit `683101636edd5e840c9a2809fc85a575add18bf7`, tree `070519796d4bbbd8e73e7f63eeb0402b86eaaab1`  
**Release target:** `0.6.0a1`; no live provider route, merge, tag, or deployment authority follows from this design

## 1. Problem

Direct Chat currently applies one global token profile to both Grok and local Qwythos. The active operator profile is only 8,192 hard-context tokens and 4,096 output tokens. Raising it globally would also enlarge Qwythos `num_ctx`/`num_predict` on an 8 GB GPU. Delegated `TaskConstraints` separately defaults to 1,024 output tokens and rejects values above 16,384, even when an exact external model supports substantially more.

Neo selected model-local settings: every provider/model pair has its own adjustable context and output policy. Local Qwythos stays conservative; external models receive larger built-in policies. T1 live work remains a separate low-cost preset and does not inherit the larger ordinary cloud defaults.

## 3. Contract

Create `ModelTokenPolicy` keyed by exact `(provider_id, model_id)`. It carries:

```text
provider_id
model_id
connection_scope
context_warning_tokens
hard_context_tokens
default_output_tokens
max_output_tokens
provider_context_ceiling_tokens
provider_output_ceiling_tokens
policy_source
policy_digest
```

`default_output_tokens <= max_output_tokens`; warning is below hard context; MACR hard values never exceed the documented provider ceilings. Policy identity excludes display labels and resident data.

`ModelTokenPolicyStore` is append-only SQLite at `settings/model-token-policies.sqlite3`. Overrides are versioned per exact provider/model. An operator override may choose values inside the immutable provider ceiling but cannot change provider/model identity, connection scope, or the provider ceiling. Active selection is also per exact provider/model; there is no global active token profile.

## 4. Direct integration

The existing global `DirectRunSettings` continues to own timeout, temperature, top-p, budget behavior, and improvement preference. Its token fields remain as a compatibility projection but are not authoritative after model-policy activation.

At conversation creation, `DirectRuntime` resolves the pinned provider/model and obtains its exact active `ModelTokenPolicy`. The canonical policy JSON and digest are stored with the conversation and combined with the global sampling/budget profile in `policy_snapshot_sha256`. Every later turn revalidates and uses that pinned snapshot. Changing an active model override affects new conversations only; it never silently changes old conversation context/output or the pinned model.

Direct conversation schema migrates additively from version 1 to 2 with nullable `model_token_policy_json` and `model_token_policy_sha256`. Existing version-1 rows remain legacy-pinned to their stored global `DirectRunSettings` token fields; they are not rewritten or silently upgraded. New rows require the exact model-policy snapshot.

The loopback API gains exact authenticated endpoints:

```text
GET /api/v0.1/model-token-policies
PUT /api/v0.1/model-token-policies
```

PUT accepts one complete versioned policy override and optional activation. The Direct UI shows a provider/model selector and edits only that model's token values. Global sampling/budget fields remain in the existing settings form. Raw prompts and history never enter the policy database.

## 5. Delegated integration

`TaskConstraints.max_output_tokens` defaults to 8,192 and permits 1..65,536. Add optional `max_context_tokens`; null means the exact model policy hard context. A non-null value must be positive and cannot exceed the resolved model hard context.

Before authority/transport, `MacrRuntime` resolves the exact provider/model policy and rejects output or requested context above that policy. It records the policy digest in dispatch context/events and T1 member identity. Provider adapters still send the exact task output bound; nothing silently clamps or substitutes a value.

MiniMax remains capped at 2,048 while MACR uses its OpenAI-compatible route. A future native MiniMax Text API is a separate route/policy and may use 10,240 only after implementation and tests.

## 6. Context measurement boundary

Direct history retains the existing deterministic local estimate and applies the model-local warning/hard values. Delegated providers do not claim tokenizer-exact measurement: existing raw-input byte and media limits remain hard, and `max_context_tokens` is an operator/model envelope rather than a fabricated exact token count. Provider-returned usage is authoritative after a call.

## 7. Safety and tests

- No policy change grants network, tool, patch, verification, acceptance, merge, deployment, or resident authority.
- No shared D runtime database is migrated during offline tests.
- Every model policy and override is digest-bound and content-free.
- Tests prove Grok changes do not alter Qwythos, overrides survive reopen, out-of-ceiling values fail, delegated limits are model-specific, and policy changes invalidate T1 member identity.
- Tests prove a model override affects only new conversations; existing conversations retain their byte-identical policy snapshot after reopen.
- All implementation follows RED -> GREEN -> refactor with focused commits.

## 8. Not in this design

No context compaction, tokenizer API call, automatic summarization, provider retry, MiniMax route migration, local-model enlargement, live provider test, invoice ingestion, or autonomous profile tuning.
