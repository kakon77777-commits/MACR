# MACR v0.6.0a1 T1 Operability and Quiet Census — Engineering Design

**Status:** Approved for offline implementation by Neo on 2026-08-30  
**Depends on:** `2026-08-30-macr-v0.6.0a1-model-token-policies-design.md`  
**Base:** exact local release `v0.6.0a0` (`6831016...` / `0705197...`)  
**Route state:** offline-only; live provider route remains stopped

## 1. Pressure findings

MSSP review established three post-release facts:

1. Concurrent review/search PowerShell command lines containing the synthetic invocation marker can make the conservative provider census fail safely. Two quiet-window full replays on the release were byte-identical and green. The initial concurrent red remains evidence.
2. `PlanQueue` exposes `list_members(plan_digest)` but no bounded global enumeration of `reconciliation_required`.
3. `PlanQueue` has no production consumer. `tests/helpers/plan_worker.py` only claims and completes synthetic rows; it never traverses authority, provider, Candidate Vault, events, accounting, or verification.

The release tag remains a valid offline library candidate, but T1 live is blocked.

## 2. Global queue observability

Add:

```python
PlanQueue.list_by_state(
    state: QueueMemberState,
    *,
    limit: int = 100,
    after_member_id: str | None = None,
) -> tuple[QueueMemberRecord, ...]

PlanQueue.state_counts() -> dict[str, int]
```

Enumeration is deterministic by `(plan_digest, ordinal, member_id)`, bounded to 1..1000, content-free, and works across every plan. A cursor is the last returned member ID and must resolve to the requested state; arbitrary or stale cursors fail closed.

CLI command:

```text
macr queue-status [--state queued|claimed|completed|failed|reconciliation_required]
                  [--limit 100] [--after-member-id <sha256>]
```

Output contains counts and public queue records only—no task body, answer, local path, credential, or remote response.

## 3. Exact T1 manifest

Create `T1ExecutionManifest` with an ordered tuple of `T1ExecutionMember`. Each member contains a complete local `TaskContract`, an `ExecutionRouteProposal`, token-policy digest, provider/model/route/role/privacy/context class, cost ceiling, and digest-only target claims. The manifest remains an operator-supplied private file; runtime SQLite stores only digests and bounded metadata.

Member digest covers:

```text
plan_digest + ordinal + TaskContract digest + route proposal digest
+ token policy digest + role digest + privacy/context class
+ cost ceiling + target-claim canonical data
```

Manifest digest covers ordered members, three-member aggregate ceiling, campaign ceiling, expiry, and dispatcher set. Duplicate members, unknown routes, model-policy mismatch, non-T1 topology, raw absolute paths, or cost-limit mismatch fail before authority or queue write.

## 4. Authority and staging

`T1Dispatcher.stage()` verifies the manifest, issues one exact `BatchAuthorityStore` record, issues one existing `DispatchAuthorityStore` record scoped to the batch and every member digest, then enqueues one `T1QueuePlan`. These records are created only by an explicit host CLI command; possession of the manifest alone is not authority.

CLI:

```text
macr t1-stage <manifest.json> --dispatcher-id <id> [--dispatcher-id <id> ...]
                               --expires-in-minutes 30
```

It performs no provider/local-model call and emits only content-free authority references and member IDs.

## 5. Production T1 consumer

`T1Dispatcher.run_one()`:

1. refuses if any global reconciliation row already exists;
2. validates both exact batch and dispatch authority;
3. claims one member with a fencing token;
4. maps it to the exact manifest member and rechecks task/route/token-policy digests;
5. invokes `MacrRuntime` exactly once through existing authority, provider lease, event, Candidate Vault, return-contract, and accounting paths;
6. records queue `completed` or `failed` only when terminal/accounting evidence is complete;
7. moves the queue row to `reconciliation_required` on unknown-after-dispatch or persistence ambiguity;
8. never retries, falls back, substitutes a provider/model, materializes, verifies on behalf of the host, or accepts.

CLI:

```text
macr t1-worker <manifest.json> --dispatcher-id <id>
                               --allow-network | --allow-local
```

One process claims at most one member. Three processes are started explicitly for a three-member batch.

## 6. Complete-path mock gate

Tests run three independent processes against one fresh D-drive test state and an injected fake external provider. The test uses real `T1Dispatcher`, `MacrRuntime`, authority stores, PlanQueue, events, Candidate Vault, return validation, accounting, and terminal evidence. Required assertions:

- three distinct claims and exactly three provider attempts;
- matching dispatch/terminal events and Candidate captures;
- exact accounting count/cost and zero unsettled rows;
- no duplicate claims, retries, fallback, corrupt evidence, raw task/answer/path in public databases;
- one injected unknown-after-dispatch produces global reconciliation and blocks further claims;
- after explicit synthetic reconciliation, remaining work can continue under a new separately authorized subject only.

This mock gate is stronger than the existing `plan_worker.py` queue-only control. The helper remains historical synthetic coverage and is not a production consumer.

## 7. Quiet census contract

The invocation predicate remains fail-closed and is not weakened with reviewer/process-name allowlists. `Test-MacrInvokerProcesses.ps1` explicitly returns exit 0 on success so `$LASTEXITCODE` cannot remain stale.

Add a verifier-only named mutex and quiet sampler:

```text
Test-MacrQuietCensus.ps1 -ConsecutiveZeroSamples 5 -IntervalMilliseconds 250
```

`verify-v06.ps1` acquires the mutex, requires five zero samples before the suite and five after all tests, and releases in `finally`. Any marker-bearing process fails the run and reports only PIDs/counts. Review seats must stop marker-bearing searches during the quiet window; the mutex coordinates updated verifiers but does not claim control over arbitrary processes.

## 8. Live limits and route gate

The future live sequence, if separately authorized, is fixed:

```text
T0: USD 0.005
reconcile T0 completely
T1: 3 members x USD 0.005, aggregate USD 0.015
campaign hard cap: USD 0.020
context/output: 128,000 / 8,192 per GLM member
serialized attempts; no retry; no fallback
```

Before live use: two quiet full gates must be byte-identical; global reconciliation count must be zero; complete-path mock must pass; legacy seal/current source row/census/accounting must be rechecked; and Neo must authorize the exact live manifest. None of those live actions are authorized by this design.
